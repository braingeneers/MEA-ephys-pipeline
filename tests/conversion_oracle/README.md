# Independent converter oracle inputs

This test kit generates native Max One and nontrivially routed Max Two acquisitions,
original typed metadata and input-only facts. It never reads converted NWBs to
construct expectations. `canonical.py`, `storage.py` and `artifacts.py` compose the complete native artifact
checker. Full corruption controls and actual caller acceptance remain separate;
successful input validation alone does not establish conversion parity.

Use the pinned public scientific runtime with Python 3.11. Generate outside Git,
then validate with the inputs mounted read-only. These mounts are local test setup.

```bash
image=braingeneers/modular-maxwell-to-nwb@sha256:46871688f9a47e4ba5dc292c2b4fdd428890f19c96778e8ee9857aa31e803e0d
mkdir -p /absolute/test-results
docker run --rm --network none -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/tests/conversion_oracle:/code:ro" \
  -v /absolute/test-results:/evidence --entrypoint python "$image" \
  /code/inputs.py --output /evidence/inputs
docker run --rm --network none -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/tests/conversion_oracle:/code:ro" \
  -v /absolute/test-results/inputs:/inputs:ro \
  -v /absolute/test-results:/evidence --entrypoint python "$image" \
  /code/validate_inputs.py --inputs /inputs --report /evidence/input-validation.json
```

The sample formula is evaluated before writing raw HDF5, and expected signal,
clock, mapping and electrode arrays are retained as `.npy`. Both selections have
partial final 200-sample chunks. Every source chunk retains offset/size/filter-mask/
compressed SHA identities. Max Two preserves both stores; selected `well002` links
to `data0001`, with different samples, geometry and length from `well000/data0000`.

Facts preserve original projection bytes and JSON types, signed zero, large
integers, unknown transport metadata and uploaded paths. The authored model has
two cell lines, a construct application and related genetic variant, three cultures,
a protocol, subject, context and two pharmacologies. Both parent cultures share a
biological ID while retaining distinct authored keys, ages, object and reference
identities. Fact schema 2 records the extension's float32 schema declaration
separately from exact binary64 storage: the pinned producer coerces finite numbers
to Python float, and HDMF 6.1.0 preserves that precision. Compare stored dtype and
hexadecimal value exactly while retaining original integer/binary64 JSON encodings.
Schema 1's float32 stored-scalar annotations were incorrect; its raw inputs and
other facts remain valid. Regenerate facts into a new directory rather than editing
old evidence or rounding a converted value for comparison.

`model.nodes` and reference payloads use logical authored keys. UUIDs generated by
conversion cannot replace canonical identity/reference checks. In ndx-cell-culture
1.0.0 `related_cultures` aliases the complete `cell_cultures` collection, including
the recorded culture; `pharmacologies` aliases `pharmacologys`. Preserve those
views without counting them as separate containers or dropping the recorded one.

The electrode contract declares all eight metadata Data payloads, four model
reference vectors and the signal's electrode region. Pinned interface/schema
sources provide default-field semantics; the checker must verify the complete
inventory and physical aliases. Measured UUIDs/file creation times require their
own validity, uniqueness and invocation checks. LINDI 0.4.6's generic-reader numeric
padding limitation remains explicit; validate exact native compressed ranges.

`canonical.py` checks complete native NWB science/model against schema-2 facts.
It checks all samples, timing, exact calibration, electrode columns, 30 canonical
containers, 13 Data payloads, every field, ordered reference targets and physical
aliases. It compares actual object identity separately from valid generated UUIDs.
Pinned schemas map the independent expected fields to physical paths/attributes;
extra objects/attributes outside the schema cache fail. Column order may vary under
NeuroConv's set-based insertion, so exact column membership and the saved
colnames/column/HDF5 bindings are checked together. ISO datetimes use HDMF's ASCII
encoding; ordinary text uses UTF-8.

For each case, provide `output.nwb` in an artifact directory and a JSON invocation
receipt named `<case>.json`. Receipts bind case/source/projection/selected raw path
and contain a successful `convert` phase with `started_at_utc` and `duration_s`;
these bound measured file-creation dates without treating them as authored science.
The report is create-only. Keep inputs, artifacts and receipts read-only:

```bash
docker run --rm --network none -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD/tests/conversion_oracle:/code:ro" \
  -v /absolute/test-results/inputs:/inputs:ro \
  -v /absolute/test-results/published:/artifacts:ro \
  -v /absolute/test-results/receipts:/receipts:ro \
  -v /absolute/test-results/reports:/reports --entrypoint python "$image" \
  /code/canonical.py --inputs /inputs --artifacts /artifacts \
  --receipts /receipts --report /reports/canonical.json
```

This checker currently requires the exact native pinned runtime. It does not
normalize expanded baseline aliases without an independent complete within-file
proof. `storage.py` adds complete chunk/filter/range, schema-cache and sidecar checks.
Companion and publication/report identities remain separate. Positive acceptance does not establish
meaningful corruption coverage, original/bridge caller parity or actual S3 execution.

`storage.py` accepts unchanged fixed-image positives using the published 0.1.6
reference above. Image 0.1.5 (digest `cd573dead65220ca87469e61e1dcf40ebe999fff6d48c9b9f0d504c86feb34ce`)
retains valid science but fails strict physical order for tiny compressed tails. The
maintained owner repairs file allocation without changing encoded chunks or numerical
dependencies. Preserve all old failures, private prototypes and their actual producer
identities. A private override does not establish immutable-image acceptance.

The checker runs the canonical checker first, then verifies every allocated signal
chunk's filter pipeline/mask, dimensions, channel-major physical allocation, file
range and native decoded values against the input arrays, including zero padding.
A single chunk-index traversal records the complete coordinate inventory before
checking every encoded range; repeated metadata lookup per chunk is unnecessary.
The sidecar root version requires the integer 1; boolean true and floating 1.0 are
not valid format versions. It also checks every schema-cache object against an independent metadata-only
reference from the installed pinned catalog. Every LINDI group, dataset, attribute,
reference, codec, inline payload and reader URL has an explicit comparison. Physical
HDF5 metadata supplies representation facts only after canonical science passes;
it never supplies expected neural/model values.

The generic LINDI0.4.6 numeric-padding limitation remains. Passing exact native
ranges and ordinary inline Zarr reads does not establish generic LINDI numeric
client compatibility. Companion, publication/report identities, meaningful
corruption controls and full caller acceptance remain separate checks.

The native local reader URL is a canonical `file://` URI. LINDI 0.4.6 interprets
that string as a literal filename; its range reader accepts filesystem paths or
HTTP(S) URLs. A generic-client probe therefore retains the original URI failure
and uses an explicitly labelled filesystem-path sidecar copy to observe numeric
padding separately. Partial chunks fail after that padding in both fixed-image
fixtures. Never rewrite the original sidecar or call the transport copy original
client acceptance.


`artifacts.py` composes the complete canonical/storage checks with selected-unit
companion, publication and final-report checks for these generated fixtures. Its
companion expectations come from the original input graph and frozen selection:
all retained metadata values/native types, complete children and aliases, exact
channel VDS selections to `output.nwb`, and every selected and aliased sample.
Unselected store/well objects are omitted under the explicit selected-unit scope.
All retained metadata must be self-contained. Variable-length source strings retain
their HDF5 type and exact values.

Receipts must declare all four effective fixture settings, including a real boolean
`create_linked_maxwell_companion`; missing artifacts never determine the option.
Enabled fixtures require four scientific siblings and the companion phase. Disabled
fixtures require three siblings and omit that phase. The old scientific output CLI
requires a companion; the separately staged, revision-pinned `runtime/verify_outputs.py`
supports omission. Its actual request/result bytes and source identity belong in
`runtime_validation` evidence, and the complete returned checks are verified.
Neither interface may fabricate success for an unrelated failure.

Every sibling name/URI/size/SHA is checked against actual bytes before its receipt
can pass. The default reviewed test publication root is
`file:///evidence/published/`; `--publication-root` can select a different explicitly
reviewed root. Each receipt's metadata-validation command must consume the final
repack output, with the same final SHA immediately before and after every later
phase. Complete report fields and all Inspector/recommended-term findings are
checked against input-only metadata and pinned validator rules. Finding order is
presentation-only; comparison preserves every field and duplicate multiplicity.
These fixtures intentionally retain four Inspector findings and three culture
recommendations per file.

`controls.py` generates actual scientific/model/reference/alias and typed transport
JSON counterexamples from copied native fixtures. Preparation retains each changed
tree, then restores the workspace byte-for-byte from the original copy. Frozen facts
are never changed. A separate check invocation mounts all generated trees read-only,
runs the unchanged complete positives and checks each negative in a fresh subprocess
with a 90-second limit and recorded peak RSS, at most two workers at once. Each negative must fail its intended
comparison with NWB schema validation still passing. A stale publication checksum or
unrelated exception cannot establish scientific rejection. Every result records actual
changed/restored hashes, schema errors, exception frames and original typed values.
The retained counterexamples are synthetic test inputs, never new producer receipts.
Physical-artifact controls and the full original oracle audit remain separate.

`/absolute/positive-modes` contains `enabled/` and `disabled/`, each with the
unchanged `artifacts/` and original `receipts/` trees accepted by the complete
checker. Preparation requires a new output; checking creates reports once. No
scientific artifacts or evidence belong in Git. These controls do not establish
original/native/MEA graph parity, live S3 or newer owner transport/runtime acceptance.

Choose an acyclic alternate reference from the frozen contract and verify that it
actually differs. A self-parent control can recurse during HDMF construction and
exhaust a container; OOM, timeout and unrelated construction failures never count as
scientific rejection. Keep such failed harnesses and their actual terminal evidence.

The parent-cell-line control removes its actual authored Data vector. A present
vector has schema-fixed shape `[1]`; its only other existing same-kind target would
create a self-parent graph. Optional absence preserves schema validity and must
fail the independent owned-Data inventory. This is a missing-authored-Data control,
not a claim of wrong-value comparison on that vector. The other Data controls use
real changed values or targets. Other model reference controls cover same-kind
alternate line targets, ordered parent swaps, duplicate targets and truncated
cardinality. A copied device alias loses the mapped link field and must fail
complete field inventory. Valid distinct UUIDs cannot hide swapped ages of
same-ID authored parents.

The wrong recorded-culture alias uses an explicit soft link to an existing canonical
parent. Soft links are allowed by the physical alias contract; an ambiguous new
hard link can instead become owned storage during HDMF readback. The control must
reach canonical object identity, without accepting an earlier constructor failure.


`artifact_controls.py` separately tests native chunk dimensions/filter/mask/order/
padding/ranges, sidecar metadata and inline values, cached schemas, selected-unit
companions, explicit options, publication identities and final report bindings. Use
the same `prepare`, `check` and read-only mount pattern as `controls.py`. Each copied
negative has an explicitly synthetic receipt; changed artifact identities and final
NWB hashes can be resealed to expose semantic comparisons instead of stale checksums.
Original producer receipts and every input fact remain unchanged. Every restored tree
must match its original baseline byte-for-byte. The complete unchanged positives and
independent unchanged neural/model truth must pass alongside intended negative failures.

Native reference URLs require strings and byte offsets/lengths require literal JSON
integers. Numerically equal floats do not establish byte-range validity: the pinned
reference reader cannot fetch such fields. Never coerce them or rely on Python's
integer/float equality. Single-range filesystem-path probes are labelled structural
checks; they do not establish original file-URI or generic LINDI numeric compatibility.
These tests do not replace actual runtime malformed-input/codec/plugin/projection
rejection controls, original/native/MEA workflow runs or live S3 acceptance.
